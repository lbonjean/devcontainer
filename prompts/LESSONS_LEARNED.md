# Lessons Learned

- 2026-09-05: Correction to the earlier immutable `sha-<commit>` advice: the current workflow reuses this tag for scheduled/manual builds and reruns of the same commit. Such builds can have different upstream inputs. Use a unique run ID plus attempt for build tags, prevent release tag overwrites in the publishing workflow, and record the image digest for exact promotion/rollback; a commit tag alone does not guarantee immutable image content.

- 2026-08-27: Devcontainer system packages belong in `.devcontainer/Dockerfile` so Docker can cache that layer. Keep user/workspace initialization in an idempotent lifecycle command.
- 2026-08-27: When `workspaceFolder` is fixed, static shell-profile and named-volume mount-point setup can be baked into the Dockerfile. Keep upstream Features for tools whose installers handle version resolution, architectures, repositories, and environment integration.
- 2026-08-27: A prebuilt image can be referenced directly with `image` and refreshed on container creation/rebuild via `runArgs: ["--pull=always"]`. This does not replace an already running container; users must rebuild it to consume a newly published tag.
- 2026-08-27: Devcontainer creation and maintenance were moved out of `msponboarding` into `lbonjean/devcontainer`. The published image is `ghcr.io/lbonjean/devcontainer:latest`; keep future devcontainer build, Feature, update, and prebuilt-image changes in that repository.
- 2026-08-27: `msponboarding` remains a consumer of the shared image through a minimal `.devcontainer/devcontainer.json` with `image` and `--pull=always`; image-owned shell configuration must be copied into the image rather than sourced from the consuming workspace.
- 2026-08-27: Ensure `/home/vscode` is recursively owned by `vscode:vscode` at the end of image setup, and create named-volume mount points such as `.codex` before that ownership pass. New named volumes inherit the image metadata; existing volumes retain their current ownership.
- 2026-08-27: Publish devcontainer builds with an immutable `sha-<commit>` tag and a movable `branch-<branch>` tag for testing. Gate `latest` on both the `push` event and `refs/heads/main` so scheduled and manually dispatched runs cannot update it.
- 2026-08-27: A Dev Container Dockerfile runs before configured Features. When build-time customization depends on tools supplied by Features, implement it as a local Feature with `installsAfter` instead of a lifecycle command; it will then be included in the feature-composed prebuilt image.
- 2026-08-27: The Azure Functions PowerShell worker `build.ps1` resolves build and publish paths relative to the current working directory, not its own script location. Change into the extracted worker source directory before invoking it from a Dev Container Feature.
- 2026-08-27: `devcontainers/ci@v0.3` pushes multiple image tags sequentially during post-job cleanup. GHCR can return a transient `unknown blob` for one tag even when the same built image publishes successfully under the next tag; distinguish this registry failure from a build failure and rerun the failed jobs to restore the missing tag.
- 2026-08-27: Do not put path filters on a workflow that is configured as a required pull-request status check. When no matching files change, GitHub does not create the check and the pull request can remain permanently blocked; run the required workflow for every pull request or make an unconditional gate job.
- 2026-08-27: When a feature branch changes workflow behavior around an action and Dependabot upgrades that action on the base branch, resolve the merge by preserving the behavioral customization while accepting the newer action version.
- 2026-09-05: The earlier advice to retain upstream Features/local worker Features is superseded for this image by the requested Dockerfile-only installation. A multi-stage Dockerfile can order tools before worker compilation and copy only published output; common-utils is already supplied by the Ubuntu devcontainer base.
- 2026-09-05: Worker 4.0.5362 bootstraps .NET 3.1.426 and 10.0.302 even when a newer LTS SDK is present. Isolate bootstrap and NuGet restore in a builder stage so those additional SDKs and caches are not shipped. Upstream protobuf tooling is x64-specific.
- 2026-09-05: `Install-Module` can emit in-use warnings and leave requested CurrentUser modules absent when installing PowerShellGet and related dependencies together. Stage with `Save-Module` outside PSModulePath, copy into the final module directory, and verify availability/imports from a fresh non-root PowerShell process.
- 2026-09-05: Resolve the Azure Functions Core Tools directory with `dirname "$(readlink -f "$(command -v func)")"`. Version 4.14.0 uses `/usr/lib/azure-functions-core-tools-4`; a hardcoded older path can silently deploy a worker into an unused directory. Validate by invoking an HTTP function with the intended worker version.
- 2026-09-05: Azure CLI 2.90.0 ships roughly 281 MB of Python bytecode cache. Removing `/opt/az/**/__pycache__` in the installation layer preserves operation and reduces image size, with a CLI startup cost and possible upstream SyntaxWarnings. An inherited empty oh-my-zsh cache directory is not a downloaded cache artifact.
