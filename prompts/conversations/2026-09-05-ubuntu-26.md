## Work and decisions

- Switched the Dockerfile from Microsoft's Ubuntu 24.04 devcontainer base to official `ubuntu:26.04`, with the native resolute Azure CLI repository and libicu78. Final installation uses official GitHub release downloads for PowerShell 7.6.5 and Core Tools 4.14.0, since both were absent from the resolute Microsoft prod feed.
- Explicitly provide vscode UID/GID 1000, sudo, git, SSH, zsh and UTF-8 locale. Retain the PowerShell Oh My Posh profile; document that Oh My Zsh customization from the previous base is absent.
- Extend image tests to verify the distribution, user identity, sudo, locale and actual PowerShell version returned by an HTTP Functions invocation.
- Initial sandbox Docker access and host network requests were denied; authorized elevated execution restored access. No missing devcontainer tools identified.
- Official Ubuntu image successfully pulled and ran; package metadata confirms native resolute Azure CLI 2.90.0.

## Failures, corrections and delivered result

- First build failed on the Microsoft prod feed signing key. Adding the official microsoft-2025.asc key fixed verification, then exposed missing PowerShell/Core Tools packages. Removed the unused prod feed and installed official standalone releases instead. Azure CLI retains its original signed repository.
- Build then hit Docker ENOSPC during non-root module installation. Windows had ample storage but Docker's 251 GB filesystem was full. Pruned unused buildcache older than 24 hours (about 591 MB plus shared references reported as 21.7 GB); shared references did not yield enough physical space. Removed four verified obsolete worker-build cache IDs from earlier repository builds (about 8.5 GB), yielding 8 GB available. No containers, images or volumes removed. Space-targeted prune attempts initially reclaimed almost nothing, and a multi-ID filter was rejected; individual-ID pruning succeeded.
- Full image successfully built as devcontainer:ubuntu26, image ID sha256:1031a5bf1caf387339b5e10cb6574b6f5f59b152a6fd348156471eefd0190b04.
- Initial extra HTTP test used Runtime, which conflicts with built-in Functions routes. Added host log diagnostics and renamed the test to WorkerVersion. The existing HelloWorld test already passed.
- Final full suite reports success: Ubuntu 26.04, vscode UID 1000, locale/sudo/write permissions, Node 22.22.2, npm 12.0.2, Yarn 1.22.22, pnpm 11.25.0, SWA 2.0.10 and native keytar, Oh My Posh 31.1.3, shell setup, gh 2.100.0, Azure CLI 2.90.0, Bicep 0.46.1, .NET SDK 10.0.400/runtime 8.0.30, Core Tools 4.14.0, all seven PowerShell modules, profile and cache checks. HelloWorld responds successfully; WorkerVersion returns PowerShell 7.6.5.
- Warnings: upstream npm dependency deprecations, Azure CLI experimental config notice and Python invalid-escape SyntaxWarning, expected noninteractive bash job-control notices, worker package missing README notice, container sysctl read-only notices during package setup. None prevented the successful build/tests.
- Validation scope is the local Linux amd64 development image; no authenticated Azure calls, cloud deployment or other Functions language runtimes tested. Core Tools docs still list installation through Ubuntu 24.04; local compatibility is verified, not a vendor support guarantee.
- Changed Dockerfile, test-image.sh, README.md, LESSONS_LEARNED.md and this conversation log. Final response in Dutch explains direct Ubuntu base, successful runtime validation, standalone installation and rebuilding the devcontainer.
- Final smoke-test process exited 0; git diff --check passed. Changes committed locally with message `Move devcontainer to official Ubuntu 26.04 and validate Functions`.
